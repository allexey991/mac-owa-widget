# Встречи Exchange в Календаре macOS (локальный ICS-фид) — дизайн

**Дата:** 2026-10-18
**Статус:** v1, согласован, в реализации.

## Цель

Показывать встречи Exchange из OWA Widget в стандартном Calendar.app рядом с личными календарями пользователя. Calendar.app подписывается на ICS-фид, который виджет раздаёт на `http://127.0.0.1`, и сам перечитывает его раз в 5 минут.

Успех: пользователь включает функцию, один раз делает подписку по инструкции во вкладке настроек, и встречи Exchange дальше обновляются в Calendar.app сами.

Не цель:

- запись из Calendar.app обратно в Exchange (ответы, переносы, создание) — календарь только для чтения;
- отдельный календарь на каждый Exchange-аккаунт — один общий календарь;
- фид для EventKit-календарей — они и так в Calendar.app, вышли бы дубли;
- HTTPS, доступ по сети, iCloud-подписка;
- данные за пределами окна синка (−7 … +30 дней).

## Результаты пробы (2026-10-17, macOS 15.5)

Проверено руками на тестовом сервере до дизайна; от этого зависят решения ниже.

- **`http://127.0.0.1:PORT/...` с Location «On My Mac» работает.** Calendar сначала трижды шлёт TLS ClientHello (пробует https), получает ответ не-TLS и откатывается на обычный http. Фид скачивает системный `dataaccessd` (`User-Agent: macOS/15.5 (24F74) dataaccessd/1.0`). Изменения подтягиваются по ⌘R и по расписанию; при стабильном `UID` событие удаляется и добавляется без дублей.
- **`webcal://127.0.0.1...` не работает:** `NSURLErrorDomain -1200` (TLS), затем `-1002`, на http не откатывается. Поэтому виджет не открывает `webcal://`, а даёт адрес `http://` для ручной вставки.
- **`file://` не работает:** Calendar отклоняет схему прямо в диалоге подписки. Сервер обязателен.
- **Location iCloud не подходит:** такую подписку качают серверы Apple, им `127.0.0.1` недоступен.

## Компоненты

Папка `OWAWidget/ICSFeed/`:

| Файл | Ответственность | Зависимости |
|---|---|---|
| `ICSFeedBuilder.swift` | Чистая функция `[CalendarEvent]` + время сборки + строки локализации → текст ICS (RFC 5545): экранирование, фолдинг по 75 октетов, `CRLF`. | нет |
| `ICSHTTPRequest.swift` | Разбор начала соединения: метод, путь, `Host`; распознаёт «не HTTP» (в т. ч. TLS ClientHello) и неполный запрос. | нет |
| `ICSFeedRouter.swift` | Чистая функция «запрос + снимок + настройки → HTTP-ответ» (статус, заголовки, тело) и сериализация ответа в байты. | `ICSFeedBuilder` |
| `ICSFeedListener.swift` | Обёртка над `NWListener`: loopback, чтение до 8 КБ с таймаутом 5 с, не больше 4 соединений, ответ и закрытие (HTTP/1.1 без keep-alive). | Network.framework |
| `ICSFeedService.swift` | `@MainActor`-синглтон по образцу `MCPServerService`: переключатель, порт, токен, статус для настроек, снимок данных из `CalendarService`. | `CalendarService`, `SecureStore` |
| `Views/ICSFeedSettingsView.swift` | Вкладка настроек «Календарь macOS». | `ICSFeedService` |

`ICSFeedService.start(calendarService:)` вызывается при запуске рядом с `MCPServerService.start(...)`.

### Поток запроса

1. `dataaccessd` делает `GET /<token>/calendar.ics`.
2. Listener читает запрос и передаёт его сервису.
3. Сервис на главном акторе берёт снимок: `events`, `accounts`, `eventCoverage`, оставляет события аккаунтов типа `.owa`.
4. Роутер проверяет `Host`, метод, путь и токен, собирает ICS и отдаёт ответ.

Сеть и Exchange в этом пути не участвуют: фид — снимок того, что виджет уже держит в памяти. Ни circuit breaker, ни `MCPAccessGuard` не нужны.

## Формат ICS

Шапка календаря:

```
BEGIN:VCALENDAR
VERSION:2.0
PRODID:-//OWA Widget//ICS Feed//EN
CALSCALE:GREGORIAN
METHOD:PUBLISH
X-WR-CALNAME:OWA Widget
REFRESH-INTERVAL;VALUE=DURATION:PT5M
X-PUBLISHED-TTL:PT5M
```

В фид попадают все события аккаунтов `.owa` из окна синка. Повторяющиеся встречи — отдельными экземплярами, без `RRULE` (виджет получает их уже развёрнутыми).

**`UID`** = первые 32 hex-символа `SHA-256(accountID.uuidString + "|" + id)` + `@owawidget`. `icalUID` не годится: он общий для всех повторов серии, и Calendar склеил бы их. Хэш не раскрывает внутренний ItemId Exchange. Фид каждый раз заменяется целиком, поэтому смена `UID` не даёт дублей.

| ICS | Источник |
|---|---|
| `DTSTAMP` | время сборки фида, UTC |
| `DTSTART` / `DTEND` | UTC с `Z`; для `isAllDay` — `VALUE=DATE` по календарю текущего часового пояса (`DTEND` — день после последнего, как в RFC 5545) |
| `SUMMARY` | `title`; префикс «Отменено: » для `isCancelled`, «Отклонено: » для `responseType == .declined` (язык приложения) |
| `STATUS` | `CANCELLED` если `isCancelled`; `TENTATIVE` если `.tentative`; иначе `CONFIRMED` |
| `TRANSP` | `TRANSPARENT` для отменённых и отклонённых, иначе `OPAQUE` |
| `LOCATION` | `location` как есть |
| `URL` | `joinURL` |
| `DESCRIPTION` | ссылка на звонок; пустая строка; `bodyPreview`; «Организатор: …»; «Участники: …» (имена через запятую). Пустые части пропускаются |
| `ORGANIZER` | не отдаётся: значение обязано быть адресом (`mailto:`), а у нас есть только имя. Организатор — строкой в `DESCRIPTION`. (Уточнение к обсуждению, где предполагалось `CN` без адреса: такое свойство невалидно.) |
| `CATEGORIES` | `categories` через запятую, каждая экранирована |

Пустые необязательные поля не порождают пустых свойств.

**Ссылка на звонок.** `joinURL` уже учитывает ссылку из поля «Место»: `OWACalendarProvider.resolveJoinURL` берёт `JoinOnlineMeetingUrl`, затем ссылку из `Location`, затем из тела. Поэтому ссылка оказывается в `LOCATION` (как в Exchange), в `URL` и первой строкой `DESCRIPTION` — намеренно: где Calendar.app ищет ссылку для кнопки «Join», Apple не документирует. Проверяется вручную на реальном фиде; лишние копии убираются по результату.

**Без `VALARM`:** виджет сам напоминает о встречах, уведомления Calendar дублировали бы их.

**Пустой фид не отдаём:** при `eventCoverage == nil` (нет ни кэша, ни синка) — `503`, Calendar оставляет прошлые данные. Иначе при запуске виджета встречи пропадали бы из Calendar до следующего опроса.

**Кодирование текста:** `\` → `\\`, `;` → `\;`, `,` → `\,`, перевод строки → `\n`, `\r` удаляется. Фолдинг: строка длиннее 75 октетов UTF-8 переносится `CRLF` + пробел, не разрезая многобайтовый символ.

## Безопасность

В фиде встречи с участниками и превью описаний, а `127.0.0.1` доступен любому локальному процессу.

- **Только loopback:** `NWListener` с `requiredLocalEndpoint = 127.0.0.1:PORT`; соединение с не-loopback адреса закрывается без ответа.
- **Секретный путь:** `/<token>/calendar.ics`, токен — 128 случайных бит (`SecRandomCopyBytes`), 32 hex-символа, хранится в `SecureStore`, сравнение за постоянное время. «Сменить адрес» генерирует новый токен.
- **Проверка `Host`:** только `127.0.0.1:PORT` и `localhost:PORT` — защита от DNS rebinding. CORS-заголовков нет.
- **Лимиты:** только `GET`/`HEAD`, запрос до 8 КБ, таймаут 5 с, не больше 4 одновременных соединений.
- **Логи без данных встреч:** debug-лог `/tmp/owawidget_icsfeed.log` и статус в настройках — время, код ответа, User-Agent.
- **Компромисс:** после подписки Calendar.app хранит встречи в своей базе (`~/Library/Calendars`) без шифрования виджета. Об этом сказано в настройках рядом с переключателем.

Ответы:

| Ситуация | Код |
|---|---|
| не HTTP (в т. ч. TLS ClientHello) | `400`, закрыть |
| неверный путь или токен | `404` |
| чужой `Host` или его нет | `403` |
| метод не `GET`/`HEAD` | `405` |
| нет данных (`eventCoverage == nil`) | `503` |
| успех | `200`, `Content-Type: text/calendar; charset=utf-8`, `Cache-Control: no-cache` |

Каждый ответ с `Connection: close` и `Content-Length`.

## Жизненный цикл

- Переключатель `icsFeedEnabled` в `UserDefaults`, по умолчанию выключен. Порт `icsFeedPort`, по умолчанию `47318`.
- Включено — listener слушает; выключено — listener остановлен, порт свободен.
- Порт занят (например, вторая копия виджета) — статус «Порт занят», без повторов в цикле. Перезапуск — при смене порта или повторном включении.
- `NWListener` в `.failed`/`.waiting` — статус ошибки с описанием.
- Пока виджет закрыт, Calendar показывает последние данные со значком ошибки обновления.

## Настройки — вкладка «Календарь macOS»

Иконка `calendar.badge.plus`, между «Настройками» и «AI (MCP)», строки через `localization.tr` (`ru.lproj`, `en.lproj`).

1. Переключатель «Показывать встречи Exchange в Календаре macOS» и строка про хранение в базе Calendar.app без шифрования виджета.
2. Статус: работает (и время последнего запроса Календаря) / выключено / порт занят / ошибка.
3. Адрес подписки (только чтение) и «Скопировать».
4. Инструкция: File → New Calendar Subscription; вставить адрес; **Location: On My Mac** (iCloud не подойдёт); Auto-refresh: Every 5 minutes. Кнопка «Открыть Календарь» копирует адрес и открывает Calendar.app.
5. Порт и «Сменить адрес» с предупреждением, что подписку придётся сделать заново.
6. Подсказка: при выключении удалить подписку в Calendar (правый клик → Unsubscribe).

## Тесты

Без реального Keychain и EventKit: токен из `SecureStore(directory:keyProvider:)` с `InMemorySecureStoreKeyProvider`.

- `ICSFeedBuilderTests`: экранирование; фолдинг по 75 октетов без разреза кириллицы и эмодзи; `CRLF`; встреча на весь день; отменённая и отклонённая (префикс, `STATUS`, `TRANSP`); разные `UID` у повторов серии; нет пустых свойств.
- `ICSHTTPRequestTests`: обычный `GET`; TLS ClientHello; нет `Host`; превышение лимита; неполные заголовки.
- `ICSFeedRouterTests`: все строки таблицы ответов; фильтр только `.owa`; `HEAD` без тела.
- Интеграционный: listener на порту `0`, настоящий `URLSession` GET.

Ручная проверка: `make run`, включить, подписать Calendar.app; встречи видны, отменённые и отклонённые помечены, изменения подтягиваются; есть ли кнопка «Join» для ссылок из разных полей.
